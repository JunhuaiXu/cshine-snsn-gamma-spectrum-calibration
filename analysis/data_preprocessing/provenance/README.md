# Source provenance

`source_manifest.tsv` freezes the historical source boundary for migrated
M1--M12 and the reviewed central M10--M12 chain. The latter includes the central event
producer, run and merge definitions, Chapter 3 diagnostic-object producers,
slow-background subtraction, the final observed-spectrum interface, and the
separately frozen central/edge comparison notebook.
The reviewed trigger-monitor and five trigger-conditioned branches, the
fast-background upstream chain, and the before/after reconstruction spectrum
producer and final notebook are frozen. The latter uses an explicit 59-group
figure manifest that is intentionally separate from the 60-group central
analysis manifest.

Each record contains:

1. a stable source ID;
2. the planned migration batch;
3. the thesis scope;
4. the path relative to the immutable historical `DataPreprocessing/` root;
5. the SHA-256 of the local read-only snapshot;
6. the hash scope;
7. the physical role;
8. the planned portable target;
9. the migration action;
10. the M0 freeze status;
11. a dependency or boundary note.

`snapshot_exact` identifies files retained byte-for-byte in the source-code
snapshot. `snapshot_sanitized` is used for notebooks whose stored outputs and
execution counters were removed during archival; their retained code cells
remain provenance evidence, but the hash is not the hash of the original
server notebook.

The manifest does not authorize edits to historical files. Original ROOT
analysis and plotting sources remain in the immutable snapshot. Portable ROOT
entries and optional Python presentation helpers are added separately and
must preserve the source ID in their provenance record.

M10 is deliberately closed in two bounded parts. M10A is the portable producer
for the central beam-on and beam-off Chapter 3 diagnostic objects and reads the
stored M8 reconstruction candidates selected by the exact M9 run manifests.
M10B retains the 32-channel trigger-monitor array and produces the trigger monitor
and five trigger-conditioned branches. The historical Fig. 15 veto policy and the
author-reviewed main-analysis policy are stored as separate object families rather
than silently merged.

The reviews that explain the selected boundary and unresolved differences are
maintained in the private thesis workspace as
`M0_SOURCE_AND_DEPENDENCY_REVIEW.md` and
`M0B_FULL_CHAPTER_SOURCE_REVIEW.md`.

`pipeline_stages.json` is the machine-readable registry for the reviewed
Chapter 3 stage graph. It records dependencies, external input contracts,
historical source IDs, portable entries, produced artifacts, ROOT objects,
thesis outputs, and unresolved questions. Validate and query it with:

```bash
python3 tools/pipeline_workflow.py check
python3 tools/pipeline_workflow.py status
python3 tools/pipeline_workflow.py trace histDiff
```

The registry contains planned stages so that missing provenance remains
visible. A planned stage with no historical source IDs is not source-frozen.

`migration_manifest.tsv` records the portable files created from the
frozen sources. It maps one or more M0 source IDs to each portable file,
records the portable SHA-256, and distinguishes migrated analysis code, scoped
build logic, regenerated dictionary declarations, command-line entries, and
validation programs. Generated dictionary source, PCM, rootmap, libraries,
executables, ROOT outputs, reports, and test products remain build or run
artifacts and are not stored in the source tree.

The local-only `reference_outputs/0308_gain_parameters.txt` is the exact plain-text array
generated by the historical central 2024-03-08 gain-relation macro. It is
retained outside the public Git file set for provenance and is not used as a
substitute for running the fit.

From the repository root, verify every non-generated portable artifact with:

```bash
python3 tools/data_preprocessing.py verify
```

When the immutable historical snapshot is available, also verify all M0 source
records with:

```bash
python3 tools/data_preprocessing.py verify \
  --snapshot-root /path/to/DataPreprocessing
```

Generated dictionary sources, PCM files, rootmaps, libraries, executables, and
run products are intentionally skipped because they are regenerated in the
selected ROOT environment.

M5 has an additional historical-artifact boundary. The surviving
`f_00.root`--`f_14.root` and `.out` files are not stored in this source tree,
and their original batch producer is absent from both the snapshot and the
bounded server inventory. `inspect_time_fit_outputs` treats those 30 files as
read-only inputs, records their ROOT object and text-summary contract, and
compares the three fitted parameters with the production table. Its generated
TSV report and input checksums remain run artifacts under `results/` or the
authorized server check directory.
